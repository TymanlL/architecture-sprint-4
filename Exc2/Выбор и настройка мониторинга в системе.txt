Мотивация
1. Бизнес-обоснование

1.1 Предотвращение потери прибыли

Быстрое обнаружение и устранение проблем до их влияния на клиентов
Сокращение времени простоя системы
Предотвращение потери заказов и клиентов


1.2 Улучшение качества сервиса

Отслеживание SLA для разных типов клиентов
Мониторинг времени выполнения заказов
Выявление узких мест в производственном процессе


1.3 Оптимизация ресурсов

Планирование мощностей на основе реальных данных
Эффективное распределение нагрузки
Обоснованное планирование масштабирования



2.Выбор подхода к мониторингу
 2.1 RED подход для пользовательских сервисов
(Rate, Errors, Duration) - для API и пользовательских интерфейсов:

Internet Shop API
CRM API
MES API

 2.2 USE подход для инфраструктуры
(Utilization, Saturation, Errors) - для баз данных и системных ресурсов:

Базы данных
S3 хранилище
Серверные ресурсы

3 Метрики для мониторинга
RabbitMQ Метрики

3.1 Number of dead-letter-exchange letters

Назначение: Отслеживание потерянных сообщений
Ярлыки:

queue_name
source_service
destination_service




3.2 Number of messages in flight

Назначение: Контроль загруженности очередей
Ярлыки:

queue_name
message_type





3.3 API Метрики

Number of requests (RPS)

Назначение: Мониторинг нагрузки на API
Ярлыки:

service_name (shop/crm/mes)
endpoint
client_type (api/web)




3.4 Response time (latency)

Назначение: Контроль производительности
Ярлыки:

service_name
endpoint
status_code





3.5 Системные ресурсы

CPU Utilization

Назначение: Мониторинг нагрузки на процессор
Ярлыки:

service_name
instance_id




3.6 Memory Utilization

Назначение: Контроль использования памяти
Ярлыки:

service_name
instance_id





3.7 База данных

Number of connections

Назначение: Отслеживание нагрузки на БД
Ярлыки:

database_name
instance_type (read/write)




3.7 Database size

Назначение: Планирование ёмкости хранилища
Ярлыки:

database_name
data_type





3.8 HTTP Статусы

HTTP 200/500 counts

Назначение: Мониторинг успешных/неуспешных запросов
Ярлыки:

service_name
endpoint
error_type (для 500)





3.9 Дополнительные метрики

Order Processing Time

Назначение: Отслеживание времени выполнения заказов
Ярлыки:

order_type
customer_type
status




3.10 Calculation Queue Length

Назначение: Мониторинг очереди расчётов в MES
Ярлыки:

priority
order_type




3.11 API Client SLA Compliance

Назначение: Контроль соответствия SLA
Ярлыки:

client_id
sla_level
operation_type





Все метрики следует собирать с интервалом в 1 минуту, хранить агрегированные данные за последний месяц и детальные данные за последнюю неделю.
