 Архитектурное решение по логированию

 Анализ систем для логирования

 Необходимые логи уровня INFO
1. Shop API
   - Создание заказа (orderId, customerId, timestamp, orderDetails)
   - Изменение статуса заказа (orderId, oldStatus, newStatus, timestamp)
   - Загрузка 3D-модели (orderId, fileId, fileSize, timestamp)
   - Расчет стоимости (orderId, amount, calculationTime)

2. CRM API
   - Действия менеджера с заказом (orderId, managerId, action, timestamp)
   - Коммуникации с клиентом (orderId, customerId, communicationType, timestamp)
   - Изменения статуса (orderId, oldStatus, newStatus, timestamp)

3. MES API
   - Начало/окончание производства (orderId, operatorId, status, timestamp)
   - Изменения в очереди производства (orderId, queuePosition, timestamp)
   - Результаты расчетов (orderId, calculationTime, complexityScore)

 Другие уровни логирования
1. ERROR
   - Ошибки интеграции между системами
   - Сбои в расчетах стоимости
   - Проблемы с загрузкой файлов
   - Ошибки в RabbitMQ

2. WARN
   - Долгие операции (>30 сек)
   - Повторные попытки операций
   - Необычные паттерны использования API

3. DEBUG (только в dev/staging)
   - Детальная информация о расчетах
   - Промежуточные состояния заказа
   - Данные интеграционного взаимодействия

 Мотивация

 Бизнес-ценность
1. Снижение времени разрешения инцидентов
2. Улучшение качества поддержки клиентов
3. Предотвращение потери заказов
4. Оптимизация бизнес-процессов

 Метрики влияния
Технические:
- Среднее время разрешения инцидента (MTTR)
- Количество потерянных сообщений
- Время выполнения критических операций

Бизнес:
- Количество клиентских обращений в поддержку
- Процент успешно завершенных заказов
- Удовлетворенность клиентов

 Приоритизация систем
1. Первая очередь:
   - MES API (критичен для производства)
   - RabbitMQ (интеграционное взаимодействие)
   - Shop API (клиентский опыт)

2. Вторая очередь:
   - CRM API
   - Базы данных
   - S3 storage

 Предлагаемое решение

 Технологический стек
1. ELK Stack
   - Elasticsearch для хранения и поиска
   - Logstash для обработки
   - Kibana для визуализации
   - Filebeat для сбора логов

 Архитектура решения
1. Сбор логов
   - Filebeat на каждом сервисе
   - Структурированный JSON формат
   - Unified logging format

2. Обработка
   - Фильтрация чувствительных данных
   - Обогащение метаданными
   - Нормализация форматов

3. Хранение
   - Отдельные индексы для каждой системы
   - Ротация по времени (daily)
   - Политика хранения:
     - Hot данные - 7 дней
     - Warm данные - 30 дней
     - Cold данные - 90 дней

 Безопасность
1. Доступ к логам
   - Разработчики: полный доступ к dev/staging
   - Поддержка: доступ к prod (с ограничениями)
   - Администраторы: полный доступ

2. Защита данных
   - Маскирование персональных данных
   - Шифрование в состоянии покоя
   - Аудит доступа к логам

 Анализ и мониторинг
1. Алертинг
   - Аномальное количество ошибок
   - Длительные операции
   - Потеря сообщений в RabbitMQ

2. Поиск аномалий
   - Необычные паттерны заказов
   - Подозрительная активность API
   - Отклонения в производительности
